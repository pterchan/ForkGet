# 结果保留与恢复

[English](recovery.md) · 简体中文

请在源分支及其基线仍可用时保存完整结果。

```sh
forkget status --id 42
forkget export --id 42 --output result.ndjson
forkget replay --engine postgresql --input result.ndjson --check
```

请使用实际分支 ID 和引擎。导出仅在结果流完整时发布文件，界面中截断的差异无法作为完整结果。结果包包含带类型的变更、目录、来源信息和生成的键。默认总量上限为 1 GiB，每条记录上限为 64 MiB。请按应用数据的要求保护文件。

回放使用原始且完整的保留世代，包括正在退役且符合条件的世代。回放无法合并到更新的基线。在带类型的校验完成前，目标分支保持独占。源分支的预算授权不会传递到目标。请使用[暂存回放和独立审查](workflow.zh-CN.md#stage-and-replay)。执行结果不确定时，请先校验现有作业，再决定是否重试。结果包不能作为元数据、服务数据库或活动事务的备份。

## 租约与失败任务

```sh
forkget renew --id 42 --ttl-seconds 3600 --expected-lease-version 1
```

请使用当前状态中显示的版本。单次租约最长 24 小时，总生命周期最长七天。续租要求分支仍处于有效状态且未过期。过期凭据以及正在删除或已删除的分支均无法通过续租恢复。现有会话会遵循续租后生效的截止时间。

作业成功后应立即删除分支。失败的 CI 作业会保留一个有明确期限的兜底租约，显式的失败回调可在总生命周期上限内续租。请保存不可变 ID，因为同名分支可能是另一条分支。保留的任务受两个物理世代和十六个原生副本槽位约束。容量冲突会显示阻塞项和清理状态，任务仍予以保留。世代开始回收后，新的引用和回放请求将被拒绝。

## 导入中断与清理

导入中断后，请使用 `fg-control snapshot status` 查看状态。使用 `fg-control snapshot retry-cleanup --id <job-id>` 重试系统已为该导入作业记录的清理操作。请勿凭推测手动删除原生对象。导入失败会保留此前处于活动状态的世代。清理失败会一直显示，直至修复。

GitHub 环境到期后需要显式重建。先用 `forkget github list` 检查，再将预期的旧分支 ID 用于 `forkget github recreate`。重复投递 webhook 不会触发环境续租或重建。请查看命令帮助，了解确切的服务提供方配置。

## 升级与恢复

协议升级须协调升级控制服务和代理二进制文件，并在恢复流量前完成仅涉及提交见证的准备工作。独立恢复原生存储或执行时间点恢复（PITR）时，须先使旧的存储实例标识失效，再启动新进程。请遵循完整的[审计升级与恢复指南](audit-recovery.zh-CN.md)，执行迁移及其余恢复步骤。

保留相互一致的元数据和原生存储备份，并保留状态、捕获和结果卷。请勿重置迁移校验和、删除审计历史，或将恢复后缺失的提交见证视为回滚证据。审计交付中断时，已知的原生操作成功结果仍可保留，此时系统会暂停受保护的新写入。重试交付不会重执行业务 DML。对于已经无法查明的事实，运维人员须显式确认其未知状态。
