# 上限与已知限制

[English](limitations.md) · 简体中文

本指南介绍 **Forkget v0.1.1** 稳定版候选的限制。生产环境和托管环境的验收须通过相应的发布门禁。

Forkget 仅接受明确列出的引擎对象、查询和命令。原生协议兼容性不代表任意 SQL、DDL 或 ORM 迁移都可执行。使用数据库模式前，请查阅[能力与支持范围](support-matrix.zh-CN.md)。超出范围的请求会被明确拒绝。

## TiDB 并发外键

TiDB 不在 v0.1.1 的发布支持范围内。此前在 TiDB 8.5.8 上，并发删除父行和插入子行后复现了已提交的孤立子行。经 Forkget 连接或直接连接使用真实 TiKV 的原生引擎时，均可复现。在使用悲观模式和预先锁定父行主键时，竞态仍然存在，回滚变体也未满足要求的等待条件。该问题尚未解决。

## 存储与保留

- 新建分支默认为只读，暂存分支始终保持只读。旧版 MongoDB 分支可能保留原有写权限，该权限会单独报告。
- 可写 SQL 分支使用原生副本。预配时间和原生存储用量随快照大小增长。只读分支共享固定的基线快照。
- 保留资源限于两个物理世代和十六个原生副本槽位。失败任务的分支不会被自动清退。刷新或新建可写分支前，请检查阻塞项。
- 单次租约最长 24 小时，分支总生命周期最长七天。请使用当前租约版本在到期前续租。
- 回放完整结果需要其原始基线仍处于保留状态。结果无法合并到更新的快照，也无法用作整库备份。

## 查询与预算边界

受支持的 SQL 范围中，每条语句的上限为 1 MiB SQL 文本、65,536 个词法单元、16,384 个参数和 1,024 条插入行。反射仅使用预先定义的逻辑目录。任意系统目录查询、客户端 DDL、加锁读、SERIALIZABLE 和任意 INSERT SELECT 均超出该范围。JSON EXPLAIN 只接受受支持的 SELECT，并拒绝 ANALYZE 和写入计划。

预算在单个事务内累计直接受影响的行数，并受事务上限、单表额度和小表最低额度约束。原生级联操作可能执行超出直接计数的额外工作。预算不累计整个 Agent 任务的用量。临时授权需要独立审查，源分支的授权不会传递给回放目标。

## MongoDB 单机部署

每个分支使用一个独立的直连客户端连接池，并禁用可重试写入。连接在首次执行分支数据命令时绑定到该分支。副本集或 SRV 发现、Atlas 部署配置以及 SQL 式多文档事务均超出支持范围。未确认写入和不受支持的单向命令会在发送给原生后端前被拒绝。

持续接收写入的单机源库无法提供全局一致的整库备份。捕获需要静止副本或一致性备份。部分写入仍视为部分完成，确认丢失的写入仍为未知。当前的 BSON 内容无法证明先前的命令曾以原子方式提交。

## 运维边界

控制服务和连接排空服务仅监听环回地址，远程控制请使用经过身份认证的 SSH 隧道。随附的 Compose 模板适用于单套本地 SQL 部署。托管服务和高可用部署超出模板范围。请验证 TLS 身份。升级或独立恢复前，请阅读[审计恢复](audit-recovery.zh-CN.md)。即使审计交付待处理，已知的原生操作成功结果仍可保留，此时系统会暂停受保护的新写入。切勿仅为修复交付而重试业务 DML。
